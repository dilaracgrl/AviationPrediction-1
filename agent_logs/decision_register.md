# Decision Register
| # | Stage | Decision | Agent Suggested | I Decided | Reason |
|---|-------|----------|-----------------|-----------|--------|
| 1 | Data Loading | Column rename strategy | Apply a single dict-based rename map after concatenating all CSVs (one rename pass, not per-file) to keep code DRY and reduce overhead | | |
| 2 | Data Loading | File discovery pattern | Use `glob.glob('data/raw/*.csv')` sorted alphabetically; assumes all CSVs in raw/ are monthly BTS files | | |
| 3 | Cleaning | Order of cleaning steps | Apply steps in sequence: (1) remove cancelled, (2) remove diverted, (3) drop ArrDel15 NaN, (4) parse FlightDate, (5) range filters on Distance/CRSDepTime/CRSArrTime, (6) deduplicate — so each step's row count is a clean checkpoint | | |
| 4 | Leakage prevention | Columns excluded from model dataset | Excluded DepDelay, DepDel15, ArrDelay, CarrierDelay, WeatherDelay, NASDelay, SecurityDelay, LateAircraftDelay, Cancelled, Diverted — all are post-departure actuals or consequence variables | | |
| 5 | Feature engineering | Derived time features | Extracted CRSDepHour (CRSDepTime // 100) and CRSDepMinute (CRSDepTime % 100) from scheduled departure time as continuous numeric features representing time-of-day | | |
| 6 | Output format | Parquet for processed dataset | Used pandas to_parquet with default snappy compression; preserves dtypes (especially datetime and int8 for ArrDel15) efficiently | | |
| 7 | Quality checks | Duplicate key definition | Key = (FlightDate, Reporting_Airline, Origin, Dest, CRSDepTime) — matches BTS conceptual uniqueness; a flight is uniquely identified by date, carrier, route, and scheduled departure | | |
| 8 | EDA | Temporal split design | Train=months 1–3, Validation=month 4, Test=month 6; month 5 excluded as a temporal buffer to prevent adjacent-month information leakage and test generalisation across a gap | | |
| 9 | EDA | Top-N filtering for carrier/airport charts | Top 15 carriers by volume, top 20 origin/dest airports by volume — ensures charts show statistically meaningful delay rates (adequate sample sizes) and avoids visual clutter from rare airports | | |
| 10 | EDA | Correlation heatmap exclusions | Excluded Year, OriginAirportID, DestAirportID from the correlation matrix — Year has near-zero variance (single year) and ID columns are surrogate keys with no inherent numeric meaning | | |
| 11 | EDA | Evaluation metrics selection | Recommend PR-AUC and F1 as primary metrics over accuracy; accuracy is degenerate at 80/20 imbalance (naive baseline scores ~80%). Brier Score added for probability calibration quality | | |
| 12 | EDA | Distance binning method | Used pd.qcut with 10 deciles (equal-frequency bins) rather than equal-width bins, so each distance group has similar sample sizes and delay rates are comparably reliable | | |
| 13 | EDA | CRSDepHour as primary time feature | Raw CRSDepTime is in HHMM integer format (non-continuous at :59→:00 boundary); CRSDepHour (// 100) is a clean 0–23 integer that models can treat as numeric or categorical without encoding artifacts | | |
| 14 | Data Loading | FlightDate parse strategy | BTS FL_DATE is exported as 'M/D/YYYY 12:00:00 AM'; original code assumed 'YYYY-MM-DD' and dropped all rows. Fixed to pd.to_datetime() without explicit format (auto-detect) + .dt.normalize() to strip time component; robust to any BTS date export format | | |
| 15 | Data Loading | Dataset scope | 7 months loaded (Jan–Jul 2025); original spec said 6 (Jan–Jun) but July file also present in data/raw/. All 7 months retained; temporal split (train Jan–Mar, val Apr, test Jun) unchanged — July becomes unused holdout | | |
| 16 | Feature Eng | Split-first ordering | Chronological split applied before any feature engineering that relies on training statistics (hub list, target encoding maps). Prevents all forms of future-data leakage into aggregate features | | |
| 17 | Feature Eng | IsMorningFlight boundary | Defined as CRSDepHour ≤ 8 (i.e., departures at or before 8 AM). EDA confirmed near-zero delay rates in hours 5–8. Hour 8 included to capture the late-morning low-delay window | | |
| 18 | Feature Eng | Cyclical encoding periods | Hour: period=24; Month: period=12; DayOfWeek: period=7. These are the natural cycle lengths. Both sin and cos are required together — neither alone encodes direction of the cycle | | |
| 19 | Feature Eng | Hub airport definition | Top 15 airports by ORIGIN volume in training set only. Volume used (not delay rate) so hub flag is a structural/capacity signal, not a target-encoded proxy. List frozen at fit time | | |
| 20 | Feature Eng | Smoothing k=100 for target encoding | k=100 means a category needs ~100 samples before its own mean is trusted over the global mean. Chosen to aggressively smooth sparse routes (many Route categories have <50 train flights) | | |
| 21 | Feature Eng | Target encoding applied to Reporting_Airline | Airline is OHE'd separately (per spec) AND target-encoded as AirlineDelayRate. The OHE captures which airline; the rate captures the expected delay magnitude. Redundancy is acceptable for tree models | | |
| 22 | Feature Eng | CRSDepHour dropped after feature extraction | Raw CRSDepHour is replaced by DepHour_sin/cos (cyclical) + IsMorningFlight/IsEveningFlight (binary) + HourDelayRate (encoded). The raw integer is not fed to the model — it conflates ordinal and cyclical structure | | |
| 23 | Feature Eng | OHE max_categories=20 | Caps each OHE column at 20 categories. Reporting_Airline has ~15 (safe). DepTimeBlk has 19 (safe). Protects against future data with new rare categories inflating feature space | | |
| 24 | Feature Eng | Test delay rate shift (28.3% vs 19.7% train) | June 2025 has materially higher delay rate than Jan–Mar. This is a real distribution shift, likely driven by summer convective weather. Model evaluation on test set must account for this shift; threshold tuning on val may not transfer | | |
| 25 | Feature Eng | OriginState, DestState dropped | State-level geographic signal is captured by: (1) hub flags for major airports, (2) OriginDelayRate/DestDelayRate per airport. Adding state OHE would introduce 50+ categories with weaker signal | | |
